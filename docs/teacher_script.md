# 45 分钟教师讲稿

课程：《从文字接龙到 AI Agent：用一个 API 构建智能体》  
对象：泛工科本科生  
课堂产出：学生能指着同一个 `agent.py`，解释上下文、消息、工具请求、实际执行和循环分别在哪里发生。

默认实时模型：**DeepSeek-V4.1-Flash**；API ID 为 `deepseek-flash`。2026-10-15 核查的官方更新页确认这一别名映射。别名未来可能更新，开课前须重新核对；录制以其实际模型字段为准。Stage 2 的公开 DeepSeek-V3 模板是刻意保留的历史教学对照，与实时模型分开说明。

本课不要求学生抄完代码。每次先看结果，再定位新增的几行。下文引号内可直接照读，其余是教师操作。PPT 的逐页安排见 [slides_outline.md](slides_outline.md)，来源与模型边界见 [sources.md](sources.md)。

六个 Tag 各自是独立教学程序。统一用 `git switch --detach <tag>` 切换，再运行 `python agent.py`；所有示例都在程序的 `$ ` 后手工输入，没有命令行参数或内置固定演示。空白行跳过，Ctrl+D 结束，Ctrl+C 平稳退出。v0 每次续写相互独立；v1—v5 保存当前会话的上下文，v5 还保留同一会话的实验文件。要开始新对话就结束后重新启动；切换 Tag 前先结束当前程序。课堂结束用 `git switch codex/teaching-cleanup` 回到最终版。

## 上课前：一次完整彩排

1. 按 README 完成 Python 环境、SDK 与执行隔离环境配置。密钥只在教师机器的环境中加载；不要把环境文件、环境变量值或终端完整环境投屏。
2. 在项目根目录加载密钥：`source ~/.config/api-keys/llm.env`。如该文件仅赋值而未 export，应按 README 的方式导出环境；不打印密钥验证。
3. 运行 `python verify_live.py`，由独立教师脚本导出六 Tag、驱动真实交互、保存录制并独立检查 CSV 报告。课堂 `agent.py` 不导入录制功能。每次源码变化后重新录制；先确认本次验证实际通过，不能仅看文件存在。
4. 手工切到六版，各用 `python agent.py` 检查任意前缀、两轮对话、自定计算和 v5 隔离目录内的后续任务。确认空白行、Ctrl+D 和 Ctrl+C 的行为；要清空对话就重新启动。v3 只做一次工具请求与回填后的回答，复杂多步任务用 v4。
5. 检查录制的模型名、时间、源码 SHA 与真实输入；在网页离线查看六份轨迹。重构前录制原样保留在 `recordings/archive/2026-10-15/pre-cleanup/`，对应 Tag 为 `archive/2026-10-15/pre-cleanup/<tag>`；第一代归档继续保留。旧版本输出不能证明精简版本已通过。REPLAY 只展示已发生的结果，不执行工具、不重新创建报告；开场要打开磁盘上的报告时，先保留彩排成品。
6. 运行 `python preflight.py` 与 `python build_viewer.py`，打开 `web/index.html`。确认六阶段能显示 `agent.py`、需要时的 `tools.py`、相邻 Tag 差异及对应真实输出；字体放大到教室后排能读清。预检和外部录制脚本都不是学生运行 Agent 的依赖。
7. 核对固定 CSV：10 个温度值为 20—29，单位 ℃。独立基准：平均 24.5 ℃、最大 29 ℃、最小 20 ℃；不要仅用模型说“完成了”作为成功依据。数据基准只在教师验证侧使用，Agent 不含固定报告验收分支。
8. v0 顶部默认 `TOKEN_STEPS = 12`、`TEMPERATURE = 0`。备课时试用把温度改成 0.8，结束后恢复 0；课堂温度对照直接修改这一处常量并重新运行，切换 Tag 前恢复默认值。当前 Tag 的录制对应默认 0；若使用归档中的 0.8 轨迹，必须说明它来自旧版本源码，不当作精简版的验证。
9. 开场与结尾可展示同一次已核实的完整轨迹。实时演示不覆盖课堂备份。单次请求超过约 10 秒尚无可讲结果时，说明切换备份，在网页明确展示 REPLAY，避免把 45 分钟变成等待网络。隔离测试无法启动时记录跳过原因，不视为通过。

时间轴中“教学 Stage 5”是新闻案例；代码 tag `v5-execution` 是执行隔离机制，放在教学 Stage 4 的后半段。两种编号不要混为两个额外课时。

## 04:00—11:00 Stage 0：从一个 token 到一句话

**04:00—05:00，切到 `v0-token`，只展示最小 API 区域。**

“这段程序主要做三件事：从环境读取密钥，设置 DeepSeek 地址，把文本前缀发给模型。我们使用 OpenAI SDK，但请求发往 DeepSeek；SDK 是客户端工具，模型服务由地址和模型参数决定。”

指出 `client.completions.create(...)`、`prompt`、`max_tokens`、`logprobs`。本例调用 DeepSeek 的 FIM Completion Beta API，只给前缀、不设后缀，观察续写。

**05:00—07:00，演示 token 记录。**

```bash
git switch --detach v0-token
python agent.py
```

在 `$ ` 后输入“牛顿第二定律告诉我们，”。默认生成 12 个 token，温度为 0；先观察实际返回，温度对照安排在下面的常量修改演示中。

“这里用的是当前Flash的文本Completion接口，不能据此断言它是未经指令训练的基础模型。我们先只关注续写形式。现在的前缀是‘牛顿第二定律告诉我们，’。每一个位置都有当前上下文、API 返回的候选 token 和对数概率，以及实际生成的 token。Token 可以是字、词的一部分或其他片段，不等于一个汉字。”

如需接受学生给出的前缀，直接在下一个 `$ ` 后输入。每次输入独立续写，不把上一次续写自动作为下一次输入；Ctrl+D 退出。

选一个位置停下：“这里只展示 API 返回的前几个候选。它们不是全部词表，概率之和不一定是 100%。我们用 `exp(logprob)` 把返回的对数概率转成更容易看的数值，没有自己编造候选概率。”

若界面逐步揭示一次 completion 的多个位置，明确补一句：“这里按位置展开同一份真实返回记录；屏幕的展示速度不等于模型实际生成速度。”若所选模型不返回 logprobs，就展示错误和已验证的真实录制，不填入假概率。默认温度 0 可能出现 0 / -9999 的退化返回，须指出它不是原始完整概率分布。

**07:00—08:20，板书唯一公式。**

`Pr[token | context]`

“token 指接下来生成的 token，context 指当前已有上下文。给定 context，得到下一个 token 的概率。选出一个、追加到上下文，再重复，就形成一段输出。这里没有一个单独的‘先写完整句子，再慢慢显示’步骤需要我们编写。”

“这些候选说明模型如何生成文本，不能直接当作答案正确的概率。它对一个 token 很有把握，整句话仍可能包含错误。”

**08:20—10:00，改变一个参数。**

结束 v0 后，打开 `agent.py` 顶部，将 `TEMPERATURE = 0` 改成 `TEMPERATURE = 0.8`，再运行 `python agent.py` 并输入同一前缀。比较结束将常量改回 0，再切下一版本。网络不稳时可使用归档中的真实温度对照，但须明确它对应重构前源码。

“Temperature 会影响采样时的随机程度。我们比较真实的两次输出：可能不同，也可能一样，尤其短前缀下最强候选可能仍然占优。一次没有变化，不说明参数无效；一次变化，也不代表高温更聪明。”

本项目实测低温为 0 时，API 可能返回采样 token 的 `logprob=0` 与其他候选的 `-9999` 哨兵值；屏幕会解释这个退化结果。不能把它讲成温度变换前的原始模型分布，更不能由显示的 100% 推断答案必然正确。正常候选概率讲解用温度改为 0.8 后的真实返回；使用归档轨迹时注明旧版本来源。

不承诺低温逐字可复现，不将两个 top-k 列表强行解释为完整采样分布。若 API 或模型模式不支持对应参数，使用彩排时确认有效的设置和录制，依据 [API 说明](sources.md)。

## 30:00—39:00 Stage 4：让结果推动下一步

**30:00—32:00，切到 `v4-agent-loop`，先看循环再运行。**

将真实代码放大，只保留学生能同时看到的一屏。按实际代码的循环变量和停止分支讲解：

“每轮调用模型。如果它请求工具，就校验、执行，把结果加入上下文，继续下一轮。如果它返回最终文本，就结束。每个任务最多 100 轮，由文件顶部的 `MAX_ITERATIONS = 100` 控制，避免无限循环。100 是上限，不是必须运行的次数。”

概念对应如下，投影时以仓库真实代码为主：

```python
for step in range(MAX_ITERATIONS):
    message = ask_model(messages, tools)
    messages.append(message)
    if not message.tool_calls:
        return message.content
    for call in message.tool_calls:
        result = execute_validated_tool(call)
        messages.append(tool_message(call.id, result))
raise RuntimeError("达到最大轮数，任务未确认完成")
```

以上是讲义示意，不是另一份需要运行的 Agent；函数名与辅助处理以 `agent.py` 为准。

## 常见现场问题的短回答

- **低温就一定正确吗？** 低温影响采样随机性；正确性需要数据、工具和验证。
- **history 是不是训练模型？** 本例只是下一次输入更长，没有更新模型参数。
- **system 能保证不被攻击吗？** 角色有助于表达指令层次，安全边界还要靠应用与执行环境。
- **工具必须由模型决定调用吗？** 应用也能强制流程；本课选择让模型请求，应用校验后执行。
- **只要写 while 就是很强的 Agent 吗？** 循环是基础机制，任务能力还受模型、工具、上下文与评估限制。
- **重放会重新生成报告吗？** 不会。重放展示真实旧结果；要生成新文件，必须重新运行真实执行路径。
- **这个终端输出是思维链吗？** 是可观察的工具请求与执行反馈，不是隐藏推理链。
