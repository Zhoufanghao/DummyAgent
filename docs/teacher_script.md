# teach：45 分钟教师讲稿

课程：《从文字接龙到 AI Agent：用一个 API 构建智能体》  
对象：泛工科本科生。课堂目标是解释生成、上下文、工具执行与反馈循环。完整源码在 Terminal 单独讲，不要求学生在幻灯片上读 SDK 字段或抄代码。

本讲稿与 [16 页 Slidev 课件](../slides/slides.md)、[逐页大纲](slides_outline.md) 同步，维持 45 分钟。第 8 页 v3 与第 10 页 v4 的完整提示词直接显示在普通 HTML 放映页，可点击“复制提示词”后切到 Terminal 粘贴；第 12 页 v5 提供空白任务输入区，现场编辑后复制，不必进入讲者备注。v0—v2 的终端输入见本讲稿与 [课堂演示提示词](../slides/课堂演示提示词.md)，第 3—7 页只显示原理、角色及模板占位示意，不展示可执行提示词或复制区。

六份 `agent_v0.py`—`agent_v5.py` 位于项目根目录，每份独立运行。提示为 `$ `；支持 bracketed paste 的终端中，多行粘贴保留换行，按一次 Enter 整段提交；空白跳过，Ctrl+D 或 Ctrl+C 结束。重启开始新对话，`:quit`、`:reset` 没有特殊命令含义。

所有 SDK 调用直接写 `model="deepseek-flash"`。别名的既往核查及公开 V3 模板依据见 [来源说明](sources.md)，不把旧记录当作本次重新核验，也不把历史模板说成当前托管 API 的内部格式。

## 上课前：预检与证据边界

准备 Python 环境并通过自己的配置加载 `DEEPSEEK_API_KEY`，不投屏密钥；程序不自动加载 `.env`。

```bash
python -m pip install -r requirements-lock.txt
python preflight.py
python chat_template_demo.py
python build_viewer.py
```

预检离线检查独立性、语法与录制 SHA，不请求 API。确认网页、Slidev 放映、讲者视图及可编辑 PPTX 可打开；在普通放映页确认第 8、10 页能复制完整提示词，第 12 页能编辑并复制现场任务，再逐份确认终端多行粘贴和退出行为。最小 `api_demo.py` 可课前用于确认 API 连通，不额外占一页或扩大代码讲解。

本次新题只做本地独立验算：v3 = **93824436**，v4 = **111303.65 元**。没有新增模型实测，不能预先保证调用次数、行动路径或成功。现有 `recordings/` 和 `verify_live.py` 保留历史同题与温度报告。需要备份回放时明确说“这是历史任务的真实录制”，不能拿它冒充本次题面的运行。

如要重新运行教师彩排，使用新目录，避免覆盖：

```bash
rehearsal_dir=$(mktemp -d)
python verify_live.py --output-dir "$rehearsal_dir"
```

该命令会请求 API，**仍采用脚本内的历史任务**，不是本次新题彩排。教师脚本在一次性目录执行，结束后仅保存转录、统计及产物 SHA，实际产物随执行目录删除；REPLAY 不执行命令或恢复文件。新课堂题可直接手工输入，但本次文档更新没有执行这些请求。

配置基线：所有阶段使用 API 默认采样设置，不传 temperature；v0 生成上限 12 token；v2—v4 固定关闭 thinking，v3/v4 生成上限为 500/1600 token。v5 的 THINKING 控制模式与 reasoning_content 显示，8192 token 由思考与回答共用，完整非流式响应后显示。六版 SDK 超时 45 秒、重试 1 次；v4/v5 无固定循环轮数上限。实际动作以 Tool Result 为准。

## 第 1 页 · 00:00—01:00 · 从文字接龙到 AI Agent

“今天追一条因果链：一个输出序列的模型，怎样进入一个能够完成电脑任务的系统？模型依然在生成，应用让生成的内容连接到真实行动，再把行动结果送回去。”

先给路线：生成 → 上下文 → 工具 → 反馈循环。课堂只在机制变化时切 Terminal，每次找一个新增环节。

## 第 2 页 · 01:00—04:00 · 任务交付需要什么

用通用任务说明：先有目标与输入，再有读取、计算或其他操作，最后交付能核对的结果。这里不启动固定温度报告任务，也不等待一次完整 API 调用。

“屏幕上写出一份报告，和目录中真的保存了一份内容正确的文件，是不同的完成证据。今天要弄清中间的动作由谁发生、结果由谁检查。”

把问题留给后文：“模型能输出文字，谁来读取文件、运行程序、保存产物？”教师在 v5 阶段自由选择现场任务。

## 第 3 页 · 04:00—08:00 · 下一个 token 的生成（v0）

先讲上下文、候选与选择，再在 Terminal 运行 `python agent_v0.py`，粘贴：

```text
牛顿第二定律告诉我们，
```

“给定已有上下文，模型生成下一个片段；把这个片段接到上下文，再重复。Token 可能是字、词的一部分或符号，不等于一个汉字。第二个片段能看见刚生成的第一个片段。”

v0 一次请求获得整段续写，再按位置展示真实 logprobs，并非每 token 发起 API 调用。生成上限为 12 token，不保证恰好 12 个。用 `exp(logprob)` 转换，top-k 不是完整词表，不重新归一化，不讲成事实置信度。只显示本次 API 实际返回的 top 候选；缺少概率时如实说明。

## 第 4 页 · 08:00—10:00 · 上下文改变，候选也随之改变

沿用刚才 v0 的输出，选择一个生成位置，依次指出当前上下文、API 返回的候选列表和实际生成项；不修改配置，也不重新解释采样参数。

“候选列表回答的是：在这个上下文中，接口返回了哪些可能的后续片段，以及它们的概率。这里只显示返回的 top 候选，不是完整词表，不能把这几项重新归一化后当作原始分布。实际生成项会加入上下文，下一位置的条件随之变化。”

请学生找到相邻两个位置，指出后一个上下文比前一个多了什么。再问：“某个候选概率高，能不能证明整句话正确？”参考答：“不能；它描述这个上下文中的续写，内容仍需核对。”

全课统一使用 API 默认采样设置。现场按实际返回值讲解，不预设每次候选、概率或续写完全一致。

## 第 5 页 · 10:00—14:00 · 对话记忆来自重新提交的历史（v1）

Terminal 运行 `python agent_v1.py`，分两轮粘贴：

```text
我的实验编号是 A102，请记住。
```

```text
我的实验编号是什么？
```

“应用保存双方对话，再把历史与新问题一起发给模型。‘记住’在本例中是相关信息重新出现在输入里，模型参数没有因此更新。”

可先在新会话只问编号，检查请求是否包含 A102；不要求模型必然答错。history 有限，输入、等待和成本会增长；长期记忆还需要额外存储或检索，本程序重启后不保存对话。

## 第 6 页 · 14:00—16:00 · messages 为上下文标明角色（v2）

“把一大段历史整理成 system、user、assistant 消息，应用能明确谁说了什么以及顺序。role 组织输入，本身不授予电脑执行权限。”

Terminal 运行 `python agent_v2.py`，可沿用前页两轮编号问答。只圈 messages 保存和重新提交这一点，不展开字典语法。v2 固定关闭 thinking，聚焦结构。

## 第 7 页 · 16:00—18:00 · Chat Template 连接消息与序列

运行 `python chat_template_demo.py`，展示随附固定公开 DeepSeek-V3 模板的序列化示例。

“结构化消息最终也需要成为模型能处理的序列。这个历史 checkpoint 的模板用相应标记串起 system、user、assistant。它说明连接的原理，不披露今天托管 API 的内部包装。”

只用项目中的一个模板，不混合其他模型标记；排版换行不等于通用角色边界。固定文件、哈希与出处见 [sources.md](sources.md)。

## 第 8 页 · 18:00—22:00 · 一次工具调用中的分工（v3）

先按页内示意区分模型与应用，在普通放映页点击“复制提示词”，再切 Terminal 运行 `python agent_v3.py` 并粘贴。页面上的完整文本为：

```text
计算((12345 * 6789 - 9876 * 5432) / 3 + 2468 * 1357) * 7 - 1233
```

“模型生成要算什么，应用解析请求并真正调用 calculator，实际结果再成为模型的新上下文。工具说明是接口说明书，计算函数才执行动作。”

依次找 Tool Call、Python 执行、Tool Result 与最终回答，不展开参数格式。工具直接用 `eval(expression)`，这是教学实现；幂写 `**`。本地有理数验算基准是 **93824436**，Python `/` 可能显示 `.0`，数值相同。

本题可由一次 calculator 完成，不要求多轮。v3 首轮可含多个调用，但只处理一轮回填；回填后不带 tools 请求一次回答。最终数字与执行轨迹都按现场输出核对，不能预设模型成功或失败。

## 第 9 页 · 22:00—25:00 · 单轮回填与持续反馈循环

指两条流程：“v3 在本轮执行回填后回答一次；v4 在回填后仍可请求工具。关键区别是新的请求有没有继续执行的通道。”

“如果后续动作需要刚才的真实结果，应用必须再次调用模型、执行新请求并继续回填。循环提供继续行动的能力，不自动证明完成。”

无需再安排历史同题实验。v3/v4 本轮使用不同任务，生成上限也不同，不作严格性能比较，更不把 v4 必然调用多次当作机制成立的条件。

## 第 10 页 · 25:00—30:00 · 采购核算：任务与规则（v4）

在普通放映页点击“复制提示词”，切 Terminal 运行 `python agent_v4.py`，将复制的三行整段作为一次输入。页面上的完整文本为：

```text
采购367件单价129.80元的材料、284件单价87.60元的材料，以及159件单价216.40元的材料。
商家规则：原价满10万元打九三折，否则打九七折；折扣后再减1280.45元优惠券。优惠后的商品金额不足10万元，另收385.60元运费，否则免运费。商品金额另加13%的税，运费不计税。
请核算最终付款金额，保留两位小数，并说明实际触发了哪些优惠和运费规则。
```

先问学生要核对哪些判断：原价适用哪个折扣？券后是否达到免运费门槛？税是否算进运费？然后查看实际工具请求和返回，不规定调用次数。

本地独立验算基准：

| 核对项 | 金额（元）或规则 |
|---|---:|
| 原价合计 | 106922.60 |
| 折扣 | 满 10 万元，九三折 |
| 折后 / 券后商品金额 | 99438.0180 / 98157.5680 |
| 运费 | 券后不足 10 万元，385.60 |
| 商品税额（券后金额 × 13%） | 12760.483840 |
| 最终付款（保留两位） | **111303.65** |

中间保留精度，最后四舍五入；逐项按分舍入在本题也得到相同终值。依据题意，税基为优惠后的商品金额，运费不计税。完整步骤见 [任务与验算](loop_examples.md)。

“这道题的难点包括规则选择和数值核算。它可以分步，也可以合并成一个表达式。v4 允许看到反馈后继续行动，但没有强制多次调用或成功保证。”

新题没有现成 API 录制；如果等待过长，可先讲本地验算与代码结构。若改看历史 REPLAY，必须明确题目不同，不能称为新题结果。

## 第 11 页 · 30:00—33:00 · Agent 的反馈闭环

沿图逐步讲：“上下文中有目标与已有证据；模型生成下一步；可能请求工具；应用执行；真实结果回到上下文；模型再决定继续还是回答。”

未知环境中可以一边观察一边行动，不必先生成完整计划。错误也能成为反馈，但本项目没有捕获所有 Python/SDK 异常，不能保证自动恢复。

“模型不再请求工具，是这个程序的循环停止条件。任务是否完成仍要独立核对，不能把停止等同于成功。”

## 第 12 页 · 33:00—36:00 · Bash 将动作扩展到文件与程序（v5）

由教师自由发挥，不提供固定提示词，不要求温度报告。先说明预期交付和验收方法，在第 12 页的空白任务输入区现场编辑，点击“复制提示词”，再切 Terminal 运行 `python agent_v5.py` 并粘贴。第 13 页继续检查本次任务的实际结果。

“计算器接表达式、返回数字。Bash 能读取文件、运行程序、保存结果，动作范围扩大；请求、执行、回填、再决策的结构没有变。”

只定位工具说明、执行、回填、循环四处，不讲命令语法。每次调用启动新的非交互 Bash，从 Agent 的启动目录开始；文件会保留，上一调用的 `cd`、变量与 `export` 不自动延续。单条命令超时 60 秒，不是整项任务的时限。

v5 的思考文本来自 reasoning_content，完整非流式响应后显示；思考中的动作不代表实际发生。脚本直接在主机目录执行 Bash，没有沙箱、命令筛选或独立验收分支；详细机制见 [Bash 说明](bash.md)。

## 第 13 页 · 36:00—40:00 · 完成任务需要可核对的结果

继续前页自由任务，围绕三类证据讲：执行证据、实际产物或结果、内容核验。若有文件，按实际路径重新打开；若没有文件，用独立方法核对输出与任务要求。

“工具退出码为 0，说明程序正常结束，但不保证逻辑和内容正确。模型写‘已完成’，也需要执行结果与任务标准支持。”

如发生真实错误，指出模型是否利用反馈改变了下一步；若一次完成，不制造戏剧性失败。学生应能指出：目标是什么，哪些操作实际发生，哪些结果仍未证实。自由任务没有预置统计答案；历史温度案例只在主动选择备用回放时出现，须说明其题目、日期及录制范围。

## 第 14 页 · 40:00—42:00 · Coding Agent 与 MCP 的位置

约 60 秒：“2025-05-16 的 Codex 研究预览展示读写代码、运行命令与测试、提供结果证据。把执行环境用于开发，再由测试结果推动迭代，可以理解 Coding Agent 的基本链条。”这仅是有日期的历史案例，不据此描述当前产品套餐或默认功能。

约 60 秒：“2024-11-25 发布的 MCP 统一应用与外部工具的连接方式。协议负责发现、描述与调用，任务循环仍由应用组织；接通工具不会自动获得目标管理或可靠性。”本项目没有实现 MCP。点击来源见 [sources.md](sources.md)。

## 第 15 页 · 42:00—44:00 · 外部材料中的指令与执行权限

用页内自拟短句说明提示注入，不现场执行攻击，不称作真实事故。

“工具结果、网页和文件会进入上下文，其中的指令可能让模型偏离原任务。输入材料不能自动成为新的操作授权。真实应用需要独立限制范围、验证参数、为敏感动作设置确认和记录。”

2025-11-24 的官方防护进展只作为历史来源；其中邮件场景是解释性假设。明确本项目直接 eval 与 Bash 尚未实现这些工程控制。权限控制也不能代替内容验收。来源见 [sources.md](sources.md)。

## 第 16 页 · 44:00—45:00 · 文字如何连接到真实行动

“模型根据上下文生成内容；应用保存历史、组织消息；结构化请求被程序变成操作；执行结果回到下一轮决策。六份文件展示这条连续变化。”

退出票：“为什么模型输出一个函数名，不等于电脑已经执行？”等 5—10 秒，再给参考答：“应用还需要解析请求，真正调用工具，再把结果送回上下文。”

## 常见问题的短回答

- **候选概率高，答案就正确吗？** 它描述特定上下文中的续写概率，事实和计算仍要独立核对。
- **history 是训练吗？** 本例只是增加后续输入，没有更新参数。
- **v4 一定比 v3 算得好吗？** 这里展示可继续处理工具请求的结构；本轮不同题不能严格比较性能。
- **v4 一定多次调用工具吗？** 不一定，题目可能合为一次计算；按实际轨迹讲。
- **循环保证完成吗？** 不能；需要验收，部分异常会直接报错。
- **REPLAY 会生成新文件吗？** 不会，只展示保存的历史输出。
- **v5 本轮一定要做温度报告吗？** 不需要，教师自由选择任务；温度案例只是保留的历史备用。

时间紧时减少候选逐项讲解和问答，保留工具实际执行、反馈闭环和结果核验。新题没有实测备份时直接说明，不把历史录制当作本次题面的结果。
