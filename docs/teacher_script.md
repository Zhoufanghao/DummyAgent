# teach：45 分钟教师讲稿

课程：《从文字接龙到 AI Agent：用一个 API 构建智能体》  
对象：泛工科本科生  
课堂产出：学生能指着六份短程序，解释上下文、消息、工具请求、实际执行和循环分别在哪里发生。

所有 SDK 调用直接写 `model="deepseek-flash"`。2026-10-15 的既往核查将其对应到 **DeepSeek-V4.1-Flash**，不把这次映射记录当作今天的重新核验；开课前须重新核对。公开 DeepSeek-V3 Chat Template 只作历史模型对照，不代表当前托管 API 内部格式。来源见 [sources.md](sources.md)。

teach 的六份文件 `agent_v0.py`—`agent_v5.py` 同时放在项目根目录，每份独立运行并内联自己需要的工具。课堂直接打开文件、运行脚本、手工输入，不切换 Git 版本。输入由 `prompt_toolkit` 提供，提示为 `$ `；在支持 bracketed paste 的终端中，含换行的粘贴作为一条完整输入保留，粘贴后按一次 Enter 提交。空白输入跳过，Ctrl+D 或 Ctrl+C 结束；重新运行即开始新对话。`:quit` 和 `:reset` 只是普通输入，没有特殊命令。下文引号内可照读，操作说明供教师使用；逐页安排见 [slides_outline.md](slides_outline.md)。

## 上课前：预检与彩排

在项目根目录创建并激活 Python 环境，安装锁定依赖；通过自己的环境配置加载 `DEEPSEEK_API_KEY`，不投屏密钥值。课堂程序不自动创建虚拟环境或配置代理。

```bash
python -m pip install -r requirements-lock.txt
python preflight.py
python chat_template_demo.py
python build_viewer.py
```

`preflight.py` 是离线检查，验证六份文件的独立性、语法，以及仓库录制与当前源码的 SHA-256，不调用 API。打开生成的 `web/index.html`，确认六份源码、相邻差异、运行命令与 REPLAY，调好投影字号。

需要新一轮真实彩排时，使用空的输出目录，保留仓库现有录制：

```bash
REHEARSAL_DIR=$(mktemp -d /tmp/dummyagent-rehearsal.XXXXXX)
python verify_live.py --output-dir "$REHEARSAL_DIR"
```

彩排会请求真实 API。教师脚本逐份复制课堂文件和数据到临时目录，输入题目、收集 stdout/stderr，并独立核对 v5 产物；结束后清理执行目录，只把输入、UTC 时间、请求模型、源码 SHA、原始输出和验收结果写进指定目录的六份 JSON。它不保存完整 SDK 请求/响应，也不保留可打开的报告文件。

如需更新网页采用的仓库录制，明确运行 `python verify_live.py --overwrite`；只更新某阶段可用 `python verify_live.py --stage v4 --overwrite`。然后再次运行 `python preflight.py`、`python build_viewer.py`。直接运行 `python verify_live.py` 会因已有录制而拒绝覆盖。修改源码后先做结构检查可用 `python preflight.py --structure-only`。

最后逐份手工启动，检查多行粘贴、空白输入、两轮对话和 Ctrl+D / Ctrl+C。v5 的手工运行直接使用主机启动目录；选择专用演示目录，放入 `agent_v5.py` 和 `data/`，文件便于现场打开。这个目录是教师安排，程序没有隔离、文件筛选或退出导出机制。

开课前只需核对以下配置与证据：

- 所有调用直接写 `model="deepseek-flash"`，SDK 超时 45 秒、重试 1 次。只有 v0 显式传 `TEMPERATURE = 0`，生成上限为 12 token；v1—v5 不传温度。
- v2—v4 固定关闭 thinking。v3 的生成上限为 500 token，v4 为 1600。仅 v5 顶部 `THINKING = True` 控制模式和 `reasoning_content` 打印；非流式完整响应返回后才显示，思考与回答共用 8192 token，完整消息进入历史。
- 当前 v3/v4 录制来自北京时间 2026-10-15 23:24，均关闭 thinking；v5 来自 2026-10-16 00:05，开启 thinking。JSON 与网页中的记录时间采用 UTC，此处换算为北京时间。它们只说明这几次实际运行，现场路径和结果仍须核对。
- CSV 的独立基准为 10 行、平均 24.5 ℃、最大 29 ℃、最小 20 ℃。检查真实文件或转录中的文件读取结果，不能只看“完成”字样。
- REPLAY 只展示已保存的输出，不执行命令或生成文件。实时请求等待过久时，说明切换录制备份；如果约 10 秒仍无可讲结果，就用已核验轨迹保持节奏。

## 04:00—11:00 v0：独立续写

**04:00—05:00，打开 agent_v0.py。**

“程序从环境读取密钥，设置服务地址，把文本前缀发给模型。OpenAI SDK 是客户端工具；服务地址和模型参数决定请求发往哪里。”

**05:00—07:00，演示真实 token 记录。**

```bash
python agent_v0.py
```

输入：“牛顿第二定律告诉我们，”。默认生成上限为 12 个 token，不保证每次恰好生成 12 个；每次输入相互独立。

“这里等待一次非流式请求返回，再逐位置展示真实响应，不是每个 token 都发一次 API 请求。Token 可以是字、词的一部分或其他片段，不等于一个汉字。每一步展示 API 返回的候选、对数概率和实际生成项。”

选一个位置停下：“只展示 API 返回的 top-k，不覆盖全部词表，概率之和不一定是 100%。用 `exp(logprob)` 转换数值，没有另行归一化或编造概率。”

温度 0 可能返回采样 token 的 `logprob=0` 和其他候选的 `-9999` 哨兵值；这是退化返回，不能讲成原始完整分布，也不代表答案必然正确。缺少 logprobs 时展示实际情况与已核实录制，不填假概率。

**07:00—08:20，板书唯一公式。**

`Pr[token | context]`

“给定已有上下文，得到下一个 token 的条件概率。生成一个、追加到上下文，再重复，就形成输出。候选概率不是整句话事实正确的概率。”

**08:20—10:00，只改温度常量。**

Ctrl+D 结束，打开 `agent_v0.py` 顶部，将 `TEMPERATURE = 0` 改为 `TEMPERATURE = 0.8`，重启并输入同一前缀。比较完恢复 0。若没有对应温度的真实录制，就保留为现场演示，不拿温度 0 的轨迹冒充 0.8。

“Temperature 影响采样随机性。两次可能不同，也可能短文本相同；一次没变化不说明参数无效，一次变化也不代表高温更聪明。低温不保证正确或逐字复现。本课只在 v0 显式传温度，后面五份使用 API 默认值。”

## 22:00—30:00 v3：一次工具请求与回填

**22:00—23:20，先运行纯文本版。**

在 `agent_v2.py` 中输入：“请计算 (12345 * 6789) / (17 + 29)。”先看实际回答。

**23:20—25:00，打开 agent_v3.py 的工具说明。**

指出 calculator 名称、expression 字符串和工具 Schema；同一文件里定位 `calculator(expression)`。

“Schema 是给模型看的说明，不是函数实现。模型写出函数名，不会自动在电脑上执行。这个教学计算器直接用 `eval(expression)` 求值，幂运算使用 Python 的 `**`，代码就在这里。”

“v3 和 v4 固定关闭 thinking，课堂先只看工具请求、执行与反馈；这两版没有思考开关，也不打印思考文本。”

定位消息进入历史的位置：“返回的 assistant 消息和后续工具结果一起保留，下一次调用才能看见之前发生了什么。”

指着 `if message.tool_calls`：“这里的‘一次’指只处理一轮工具请求。一条响应可以包含多个 tool call，程序用 `for` 全部执行并回填；随后第二次请求不再携带 tools，只获取回答。它没有继续处理下一轮工具请求的循环。”

**25:00—27:00，运行同一计算。**

结束 v2 后运行：

```bash
python agent_v3.py
```

输入：“请用 calculator 计算 (12345 * 6789) / (17 + 29)。”

依次指出模型 tool call、Python 调用 calculator、实际返回值，以及带对应 tool_call_id 的 tool 消息。

“这行 Python 才产生计算结果。模型仅仅输出 `calculator(...)`，并不等于电脑已经执行它。”

**27:00—28:30，画数据流。**

```text
LLM → Tool Call → Python Function → Tool Result → LLM
```

“tool_call_id 对应请求与结果。结果重新交给模型，它才能解释数值意味着什么。Tool Call 是请求，Tool Result 才证明程序实际执行了什么。”

**28:30—30:00，在 v3 中提出需要反馈后继续计算的任务。**

用 Ctrl+D 结束简单计算会话，重新运行 `python agent_v3.py`，输入下面完整题目；真实彩排轨迹可作时间不足时的备份。

```text
先用calculator计算123456789 * 987654321，得到整数A后，取A的末6位作为B；
再用calculator计算B**3 + 17 * B。请给出A、B和最终整数。
每次只请求当前一步的计算，必须等工具返回后再进行下一步，不要把整条流程合成一个表达式。
```

“这次题目明确要求：先拿到第一步工具结果，再决定下一次输入，不能把整条流程合在一次计算里。”

当前 `recordings/v3.json` 中，v3 只执行第一步，得到 `A = 121932631112635269`；正文出现未执行的 DSML 调用，没有终值，应称为“未完成”，不能说算出了错误数字。

“模型也可能自行算出后续结果。现场先检查终值，再数实际 Tool Result；如果数值正确，就如实说明，同时检查题目要求的后续工具步骤是否真正执行。正文里的调用描述不能当作执行证据。”

## 30:00—33:30 v4：持续反馈循环

**30:00—32:00，打开 agent_v4.py 的 while True。**

“调用模型、保存返回消息。如果请求工具，就执行、把结果加入 messages，继续下一轮；如果返回最终文本，就结束当前任务。这里没有轮数上限，`while True` 直到代码中的结束分支才退出。”

用网页相邻差异圈出循环，对照刚才 v3 在第一次回填后进入最终回答的路径。

“第一步结果回来之后，v4 还会带着工具定义再次调用模型，因此能真正执行下一步。我们沿用同一题，只改变是否继续处理工具请求。”

**32:00—33:30，在 v4 新会话中输入完全相同的题目。**

```bash
python agent_v4.py
```

粘贴刚才完整题目，不改计算步骤或要求。圈出第一步 Tool Result，以及下一次请求中由它得到的 `B = 635269`。

下表是独立整数计算的标准答案。当前 `recordings/v4.json` 中，v4 实际执行两次 calculator，结果与标准答案一致：

| 核对项 | 整数 |
|---|---|
| A | 121932631112635269 |
| B（A 的末 6 位） | 635269 |
| B³ + 17B | 256373415452969682 |

“循环使下一次决策看见上一轮真实反馈，并让后续请求得到执行。v3 和 v4 当前都关闭 thinking，不预设 v3 失败；模型可能合并表达式或自行算出结果。比较的是程序是否继续处理工具请求，每次仍核对 Tool Result、步骤和最终数值。”

备用的条件分支三步题、标准答案和实测记录见 [循环对照案例](loop_examples.md)。课堂主讲使用上面的两步题，保持 45 分钟安排。

## 33:30—39:00 v5：Bash 执行

## 39:00—43:00 应用案例与收束

## 常见问题的短回答

- **低温一定正确吗？** 温度影响采样，正确性仍要验证。
- **history 是训练吗？** 本例只是增加后续输入，没有更新模型参数。
- **工具一定由模型选择吗？** 应用也可以固定流程，本课让模型发出请求。
- **循环自动保证完成吗？** 不能；要检查实际执行与产物。普通 Python/SDK 异常会直接报错，代码没有自动恢复分支。
- **REPLAY 会重建报告吗？** 不会，它只展示已保存的 stdout。
- **v5 的思考文本从哪里来？** 来自 DeepSeek API 的 `reasoning_content`，由 v5 的 THINKING 开关控制，完整非流式响应后显示。v2—v4 固定关闭 thinking，实际执行仍看 Tool Result。

时间紧时先用真实 REPLAY，减少温度比较和问答，保留 30—39 分钟循环演示；应用案例各用一句话压缩，始终讲清模型请求与程序执行的区别。
