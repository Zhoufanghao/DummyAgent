# v3 / v4：同题展示反馈循环

在两个终端分别运行 `python agent_v3.py` 和 `python agent_v4.py`，输入相同题面。先按项目 requirements 安装 OpenAI SDK 与 `prompt_toolkit`；输入提示为 `$ `。在支持 bracketed paste 的终端中，整段粘贴含换行题面，粘贴后按一次 Enter 提交，换行会保留在同一条输入中。空白输入跳过，Ctrl+D 或 Ctrl+C 结束。题目要求逐步调用，让后续计算使用刚返回的结果。两版 calculator 完全相同，直接使用 `eval(expression)`，幂运算写 Python 的 `**`；区别在于 v3 回填一次后直接回答，v4 继续给模型调用工具的机会。

## 主案例：取末六位，再计算

```text
先用calculator计算123456789 * 987654321，得到整数A后，取A的末6位作为B；
再用calculator计算B**3 + 17 * B。请给出A、B和最终整数。
每次只请求当前一步的计算，必须等工具返回后再进行下一步，不要把整条流程合成一个表达式。
```

| 步骤 | 标准结果 |
|---|---:|
| A = 123456789 × 987654321 | 121932631112635269 |
| B = A 的末六位 | 635269 |
| B³ + 17B | 256373415452969682 |

## 备用案例：观察奇偶，选择分支，再求余

```text
先用calculator计算987654321**2 + 123456789得到整数A；看工具返回的A末位：若为奇数，下一步计算A * 123457 + 76543；否则计算A * 76543 + 123457，得到B；最后用calculator计算B % 1000000007。请给出A、B和最终余数。每次只请求当前一步的计算，必须拿到工具结果后再选择下一步，不要把流程合成一个表达式。
```

| 步骤 | 标准结果 |
|---|---:|
| A = 987654321² + 123456789 | 975461057913427830 |
| A 为偶数，B = A × 76543 + 123457 | 74664715755867506515147 |
| B % 1000000007 | 499882649 |

## 本次实测与课堂判读

2026-10-15 使用 `deepseek-flash`、温度 0 真实运行两份程序：v3 两题都只产生第一步的 `Python → Tool Result`，后续调用出现在助手正文中，没有执行，也没有给出最终数值；v4 分别实际执行两次、三次 calculator 调用，最终结果均与独立整数计算一致。

真实输入、时间、原始终端输出及源码 SHA 保存在 `recordings/v3.json`、`recordings/v4.json`；可用 `python verify_live.py --stage v3 --stage v4 --output-dir /tmp/loop-rehearsal` 重新彩排。网页展示这两份录制，不运行历史输出中的命令。

课堂上先检查最终数值，再圈出每条真实的 `Python → Tool Result`。助手正文里的函数名、DSML 标记或“接下来调用”都不能充当执行证据。本次 v3 的结果应称为“任务未完成”，没有错误数值可供判断。

这些是多步操作练习，逐步约束直接写在题面中。当前 calculator 可以接受完整 Python 表达式，模型也可能合并运算或自行算对；出现这种情况，应如实记为完成。固定数学题不能保证 v3 每次失败，v4 的循环也不保证每次成功；现场以实际输出为准。
